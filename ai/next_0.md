# Next 0 — implementation summary and what's next

Implements `ai/plan_0.md` (answering `ai/prompt_0.md`). Nothing is committed.

## What was built

**Engine and stack (M0)**
- Vite 8, plain JS with JSDoc types (`npm run typecheck`, clean), no UI framework.
- noa copied from `develop@8a74866` into `vendor/noa`. **It runs on Babylon 9.26**, so the Babylon 6 fallback wasn't needed. Three small patches are listed in `vendor/noa/UPSTREAM.md`. One of them was essential: Babylon 7+ changed the diffuse sampling macro, and without the patch the texture atlas rendered as stripes.
- Origin rebasing is turned off (worlds are at most 256 wide), so all meshes use world coordinates.

**World (M1)**
- Deterministic, versioned terrain generator in a worker (`src/world/gen/terrain_v1.js`): hills, mountain ridges, an island falloff with a sea, caves, iron/gold ores, trees, a plaza, and the Town Center structure. It uses only integer hashing plus `+ - * / floor sqrt`. Golden-hash tests guard it against drift.
- The worker pre-generates the default world's spawn chunks **while the menu is still showing**.
- `WorldState` is terrain + edits overlay + night-damage overlay. Every permanent change is an op that goes through `SyncService` (`LocalSync` echoes it back).
- World file format, export download, a build-time world list (`virtual:world-list`), `worlds/default.world.json` (a walled town with 4 arrow towers and 4 troops, generated by `tools/make-default-world.mjs`), and IndexedDB autosave with a **Continue** button.
- Procedural 16px texture atlas (no download), 23 block types, inventory, 9-slot hotbar, crafting recipes.

**Characters (M2)**
- `tools/blender/make_characters.py` runs headless and doesn't touch the open Blender session. It builds 8 characters (player, swordsman, archer, gunner, grunt, skeleton raider, brute, sapper) on one shared rig, with a painted 64×64 texture each, 16 clips, and `items.glb`. The script checks its own bone axis conventions before exporting.
- Each GLB is ~111 KB raw / ~8 KB brotli. All pass `npm run validate-glb` (Khronos validator + contract checks).
- Runtime: lazy glTF loader, PBR materials swapped for StandardMaterial, layered animation (locomotion + arm-only hold poses + upper-body actions via `AnimationGroupMask`), fallback clips, item sockets.
- Contract: `docs/character-contract.md`. An external avatar loads with `?avatar=<glb url>` and falls back to `player.glb` if it fails.

**Tower defence (M3)**
- Day/dusk/night/dawn cycle with sky, fog, a sun/moon disc and a moonlit night.
- Town Center HP; wave budget = base × 1.18^level + a small share of defence value; sub-waves; per-tier attacker cap (extra budget becomes HP instead of more bodies).
- Flow-field navigation in a worker (`src/ai/navCore.js`): a "walker" and a "digger" profile; walls are breakable at a cost; fields rebuild at most every 0.7 s after block changes.
- Attacker brains (fight nearby defenders, break walls in the path, sappers dig, attack the Town Center, get-unstuck fallback). Defender brains (guard post with a leash).
- Arrow and cannon towers, spikes, gates, and projectiles/particles as thin instances (one draw call each).
- Night damage is restored at dawn, defenders revive, rewards on survival, and the night level stays the same after a loss.

**Roles and modes (M4)**
- Aerial camera (WASD/drag/wheel, click a unit to play as it at night, right-click places blocks by day), possession of any defender or attacker in first or third person, role picker at dusk and on death, waiting for the next attacker of a chosen type.
- Creative mode (always day, unlimited items, night strength slider with a wave preview) and a daytime skirmish option.
- Touch: virtual stick, drag to look, pinch zoom, tap units, action buttons, narrow-screen layout.

**Polish, performance, net (M5/M6)**
- Procedural Web Audio: positional digging/breaking/combat sounds, night horn, dawn chime, win/lose stings.
- Quality tiers from device hints, refined by the GPU renderer once the engine exists, plus an FPS governor that steps down.
- `IdentityService` / `SyncService` interfaces with local implementations, a background `config.json` probe (ships as `{}`), and `docs/protocol.md` for the generic servers.

## How it was verified

- `npm run check`: type check clean, **23 unit tests pass** (worldgen golden hashes, nav fields incl. going around and through walls, world file round-trip + committed default world, waves, inventory, cycle, clip names), all GLBs valid.
- `npm run build`: budget check passes. Brotli sizes: menu 4.8 KB, game code 309 KB, worldgen worker 3.7 KB, default world 0.7 KB, player model 7.9 KB (total **326 KB** to first playable frame).
- `npm run perf` / `perf:mobile` (Chrome, HTTP/2 + brotli, 10 Mbps, 40/70 ms RTT, Intel RPL-P iGPU):

  | Profile | Menu interactive | First playable frame | Night bench |
  |---|---|---|---|
  | desktop | 0.11 s | 1.40–1.45 s warm, 2.4–2.5 s on a cold GPU/browser start | ~54 fps, ~18 units, tier high |
  | mobile (4× CPU, touch, 412 px) | 0.19 s | 1.3–1.8 s | ~58 fps, tier med |

  All runs are under the 4 s spec maximum. The cold-start case sits right at the 2.5 s target.
- Scripted browser play-throughs covered: menu → Play / new creative world / Continue; mining through the real control path; placing blocks and troops; picking a troop back up; export snapshot; autosave; start night → waves path to the Town Center → towers and troops kill attackers → wall damage → dawn restores it → day 2 with rewards; Town Center destroyed → night lost; possession of a defender and an attacker (including waiting for a spawn), death → role picker, real mouse click in aerial view → possession; skirmish spawns; touch stick/look in mobile emulation.

Bugs found and fixed during verification: the atlas shader regex on Babylon 9, dark character textures (sRGB buffers), the aerial camera being clamped into the ground, aerial picking (missing `Ray` side-effect import and double hardware-scaling), an ASI hazard in the worker `postMessage` calls, brutes too tall for 2-block clearances, and the menu becoming interactive late because tier detection created a WebGL context.

## Where it differs from the plan

- **Default world size is 192** (menu offers 128/192/256) instead of 256. It keeps aerial view and nav cheaper on phones.
- **Edits store block names inline** (`[x,y,z,"stone_wall"]`) instead of a palette + index. Slightly larger, much more readable in git diffs.
- **The default world is generated by a script**, not played and exported. `tests/worldfile.test.js` checks the committed file matches the script. Delete that test if you hand-build it in game.
- **Chunk size stayed 24**; I did not measure remesh times for 16/24/32.
- **Baked-vertex-animation crowds were not built.** Crowd cost is controlled by tier caps on attackers, freezing animation on far/over-budget units, and turning extra wave budget into HP.
- **The FPS governor only steps quality down**, never back up.
- The brute's collision box is 1.9 tall (the model is ~2.2), so it fits 2-block gaps.

## Known issues / limits

- **Not tested on real phones.** Mobile numbers are Chrome emulation with the CPU throttled; the GPU wasn't throttled. Real entry-level GPUs (Mali/Adreno 6xx) may need the low tier or fewer attackers.
- The night benchmark had ~15–20 units; the high tier allows 70 attackers at once, which hasn't been measured.
- Entity shadow discs render through walls.
- Held item orientations are only roughly tuned (`ITEM_POSE` in `src/characters/library.js`).
- Units only soft-separate; crowds can overlap.
- There are no HP bars over units, no music, and no tower firing animation.
- Losing pointer lock (Esc) always opens the pause menu on desktop, by design.

## What to work on next (suggested order)

1. **Test on a real low-end phone and an older laptop**, then tune `TIERS` and wave caps in `balance.js`. Add VAT crowds only if skinned units turn out to be the bottleneck.
2. **Balance pass**: day length, wave growth, recipe costs, ore frequency (gold is rare), tower stats. Everything is in `src/game/balance.js`.
3. **Readability in combat**: unit HP bars (a thin-instance billboard), damage flashes, a Town Center hit effect, attacker path previews in aerial view.
4. **Better placeholder art**: item attach poses, a Town Center banner, tower firing animation, a sky gradient/stars.
5. **Hand-build a nicer default world in game** and export it (then drop the script-match test).
6. **Multiplayer groundwork**: a reference generic sync server (WebSocket relay + ordered op log per `docs/protocol.md`), a `RemoteSync` adapter, presence for player transforms, host-authoritative NPC state.
7. Optional: in-browser remesh timing for chunk sizes 16/24/32, and an FPS governor that also steps quality back up.
